# Slow Mail: working rules

- **Commit straight to `main` and push. Never open a pull request on this repo.** Commit subjects are conventional (`feat:`, `fix:`); the release drafter bumps from the subject.
- `js/dist` is committed and is what forums load. After any change under `js/src`, run `npm run build` in `js/` (from a fresh `npm ci`) and commit the bundle; CI fails if it is stale.
- Publishing a release is Ernest's click. Nothing is announced until he says so.

## Design rules that exist for a reason

- **A letter on its way doesn't exist for its recipient.** Not in any answer, include, search or notification until Mailroom delivers it. `Access\ScopeLetterVisibility` (registered with `Extend\ModelVisibility`) is the one gate: every letters query, the `slow-mail-letters` resource (`Api\LetterResource`, its scope and `Search\LetterSearcher`) goes through it. The words are decrypted for output in one place: LetterResource's `body` field, on a single letter (Show) only. Nothing in Flarum relates to this type, so no include can reach a letter. Notification subjects are Users (a subject without an API resource 500s every notification list); the letter id rides in the data. Add any new endpoint or include to `PrivacyTest::assertNowhere()`.
- **Resources, not hand-rolled JSON**: letters, reports (`slow-mail-reports`) and pen-pal listings (`slow-mail-seekers`, own only) are `AbstractDatabaseResource`s; the frontend reads and writes them through `app.store` (models in `js/src/forum/models`, `Extend.Store`). Only four plain handlers remain, each with its reason in its docblock: the summary, the journey quote, the block toggle and the ranked matches. Refusals throw `Refused` (a `KnownError`): its code is the error code, extend.php maps it to 422/429.
- **Nobody else reads letters, admins included,** except one its recipient reports: ReportResource copies that letter's words (encrypted) into a moderators-only list (`slow-mail.moderate`), and a queued job (`Job\NotifyModerators`) tells them. Encrypted at rest (`Vault`, XChaCha20-Poly1305, sender:recipient as associated data); the key lives on the `ernestdefoe-slow-mail` disk (`storage/slow-mail/key`) or config.php `slow-mail.key`, never in the database, is read each time (never kept on the instance: workers must notice a change) and only created while there are no letters. Its fingerprint (`slow-mail.key_check`) is saved with the first letter: a missing or changed key stops sending with 503 and a critical log.
- **Travel times never place anyone more precisely than Member Map does.** `Journey` uses a distance only when EACH member can see the other on the map (`PlaceSource::seenBy`: `MemberMapPlaces`, Member Map's own `MemberQuery`); otherwise the admin's set time. The distance is banded by the coarser precision (city 500 km, region 1,000, country 2,000; never band 0), then jittered by up to a whole band from an HMAC over the key, the pair and their places (stable, so repeats can't average it away), then arrival rounds up to the hour. `JourneyTest` solves exactly which distances fit an observed time: keep it passing when touching the formula. Postmarks come from the country code (and the region at region precision), never a city; no country code, no place.
- **Other extensions only through `Extend\Conditional`**: Member Map binds `PlaceSource`; Parley (its own `Relations` service), fof/byobu, flarum/messages and flarum/suspend each add an `Integration` (`Extend\Integrate`, tagged). Nothing checks `isEnabled()` or reads another extension's tables. List any new one in composer.json `optional-dependencies` and `suggest`.
- **Refusals all look the same** (`slow_mail_not_accepting`): blocks (ours and Parley's, both ways), "who can send me letters", the integrations, unconfirmed or without the permission. Pen-pals-only counts only DELIVERED letters (one in transit must not be given away).
- **Delivery is idempotent**: a conditional UPDATE claims each letter; only the winner notifies; `notified_at` retries a failed notify. Scheduler every minute + `DeliverOnVisit`, which queues `Job\Deliver` once a minute at most after an arrival is due (one cache read otherwise). A block since sending returns the letter, and so does a sender since suspended or without `slow-mail.send`. The cached next arrival lives an hour at most.
- State changes are POST/PATCH/DELETE only (reading a letter is `PATCH {read: true}`: a GET could be fired by an `<img>`).
- A moderator's GDPR export of a member has counts and dates only; who they wrote to, postmarks and words only in their own export (`Gdpr\ExportActor`). flarum/gdpr builds export types with `new`, so `SlowMailData` resolves the Vault (commented).
- Letters render as text nodes (`white-space: pre-line`), never HTML. Stamps and postmarks are SVG drawn in `js/src/forum/art.tsx`, called as functions (Mithril treats a function used as a JSX tag as a closure component).
- extend.php uses string literals only (no class constants at load time).
- **PostgreSQL:** never bind the same value twice into an expression that appears in both SELECT and GROUP BY (it becomes two different expressions); write a cast int into the SQL instead (`Pals`). SQLite treats an unknown double-quoted column as a string, so a wrong sort column passes there: always run MySQL and PostgreSQL too.

## Testing

- `composer test:setup && composer test` (integration; prefixed SQLite, MySQL and PostgreSQL all pass; on PostgreSQL never use a `pg_` prefix, it collides with the system catalogs), `composer analyse:phpstan`.
- `cd js && npm ci && npm run build && npm run format-check && npm run check-typings`.
